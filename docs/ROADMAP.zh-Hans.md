# Nifro 路线图

[English](ROADMAP.md)

Nifro 的核心想法是：网页可以成为桌面的一部分。这份路线图区分还需要证据的假设、已经准备实施的工作、已经塑造当前 App 的决定，以及明确不再做的方向。旧编号如 `P`、`L1`、`K7` 保留为代码注释和旧设计文档的索引，不代表优先级。

## Trying

### 降低闲置壁纸的资源消耗（`P`）

Nifro 目前会持续渲染，直到被关闭、屏幕锁定，或按设置在电池时暂停。旧功耗子系统已经移除：它的渲染后端、遮挡检测和静帧判断都在回答「现在谁在渲染」，而 Browsing Mode 也会改同一个事实，多个所有者最终互相冲突。重新做之前必须测量被遮住的闲置壁纸，只保留一个渲染状态所有者，并提供明确、可逆的关闭方式；它必须在目标状态胜过现有基线。

### HDR 和多显示器真机验证（`K7`、`D4`、`D6`）

没有代码或 entitlement 处理 HDR。先用真实 HDR 源和硬件测量整条管线。也要验证没有菜单栏的副屏，以及两块尺寸、backing scale 不同的屏幕；剩下的风险是系统几何和像素，而不是没读过的代码。

### 跨屏共享画面（`V3`）

旧同步功能已移除，因为独立页面、时钟和控制会逐渐产生矛盾状态。探针证明 `SCShareableContent` 可以在不授予屏幕录制权限时捕获 Nifro 自己的桌面级窗口，但这仍是实验：只测过单张捕获，连续 `SCStream`、颜色管理、独立裁切、follower 交互和不同屏幕布局仍未解决。见 [搁置的设计](shelved/MULTI-DISPLAY-SYNC.md)。

## Planned

### 桌面块（`L1`–`L4`）

让地图、仪表盘或小型实时网页只占桌面的一部分。模型是自由摆放加吸附网格，位置存为比例。块是窗口的基础 frame，可见性只能在其内部收缩，不能反过来定义它；每个块有独立 web process 和数据存储，并在壁纸上而不是标题栏窗口中摆放。

### 页面状态、面板和媒体（`M3`、`M5`、`M6`、`W1`–`W5`、`V1`–`V5`）

Nifro 记住自己的设置，网站记住网站自己的状态。URL fragment 和滚动位置有时能恢复位置，Floor796 一类网站未必能恢复内部缩放。按网站保留本次运行中的 `WKWebView` 是可选方案，但不能破坏隔离。

面板计划补上重新启用、重载、立即随机、保存安全地址和旧菜单清理。面板控制**显示器**，Websites 窗口编辑**记录**。媒体控制先要有按页面的状态上报；GIF 需要全分辨率捕获、有上限的内存和硬停止。

### 目录、可靠性和发布（`S1`、`K1`、`K6`、`E23`、`E25`、`U2`）

先审核 featured 站点。Bilibili 登录和 YouTube 播放是两件事；YouTube 已测过的 `Referer` 解法，在 WebKit element fullscreen 会破坏 Dock（`K40`）的问题解决前继续搁置。其余工作包括审阅帮助文案、版本化设置迁移、运行或删除失效的 SwiftLint analyzer rules、开启 release immutability；Sparkle 要等 appcast、签名和 sandbox 安装服务的长期承诺值得承担。

## Done

- **播放列表和独立显示器：** 显示器选择播放列表；复制列表会新建 ID，因此裁切和登录彼此隔离。
- **按显示器存状态：** 加载失败、关闭状态和 Browsing Mode 都按显示器为键，面板读取所属 scene。
- **裁切：** 存页面位置和放大倍数，而不是固定像素，所以能跨不同显示器形状适配。
- **以显示器为中心的面板：** 每块屏一列，展示自己的页面、状态、错误和控制。
- **可靠性：** 真正的 reload 会复用页面；缩略图共用数据存储清扫；面板被遮住后停止截屏；旧网站数据仍可解码。
- **构建和发布：** 稳定本地签名保留 sandbox 和 bookmark；按架构通过 GitHub Releases 与 Homebrew 发布。

## Not Do

- **不重写引擎或框架（`X1`–`X4`）：** 问题在调度和 AppKit 窗口行为，不在缺少 Web 引擎、生成器、DI 或插件框架。
- **不做高风险或静态替代（`X7`–`X11`）：** 摄像头/屏幕输入跨越不必要的权限边界；静态图片丢掉实时交互；Chrome 窗口没有公开桌面层 API；不透明页面和可配置 reload 没有量出的价值。
- **不在面板重复功能（`X12`–`X14`）：** 现有本地化够用，网站编辑和快捷键配置都不属于显示器控制面板。
- **保留已审查机制：** 透明 `WKWebView` KVC、`NSStatusItem` + `NSPopover`、`ScrollableTextView`、security-scoped bookmark、图片缓存、图标获取和 80 ms 预览循环都有具体 API 或行为依据。
- **平台边界（`K40`）：** element fullscreen 保持关闭，因为在这种 accessory-app 配置中它能销毁 Dock 的在屏窗口，App 侧没有缓解办法。
